# 莱茵生命 · 调查线索板设计稿 v1

日期：2026-09-18。交付性质：界面、场景与交互设计；尚未接入真实 Agent。

技术调研与工具契约见 [第一阶段调研方案](rhine-agent-evidence-board-phase1.md)。本稿将其转成可供视觉和功能实现的明确要求。

## 1. 设计目标与场景改造范围

**透明的操作层在眼前，一项正在展开的调查在后方：重要线索围绕中央报告逐步建立联系。**

用户已确认：现有场景可以根据功能需要调整。本稿允许改变线索板的板面、边框、支撑结构、镜头取景、邻近档案位置与照明；现有白板的尺寸、装饰铭牌、固定纸片位置不再作为必须保留的约束。

保留的视觉特征：暖白档案世界、墨色字、莱茵生命工业细节、透明悬浮操作感。当前性能档作为实现预算；视觉提升主要来自构图、层级和运动秩序。

主方案是**中央留空的研究区**：档案在外围形成空间，中央清楚容纳一个调查事项。历史调查切换时复用这片研究空间，不把数十块实体白板并排摆进场景。

## 2. 场景分层

| 层级 | 内容 | 设计要求 |
| --- | --- | --- |
| 远景 | 暖白档案阵列、低对比的空间结构 | 延续现有世界；在阅读主区后方减少高频书脊、强斜线和标签 |
| 中景 | 当前调查的研究板 | 更宽、更薄，支撑与厚重边框退到视线外围；中央浅色工作面维持内容可读性 |
| 板上内容 | 小纸片、关系签、时间条、对照卡 | 有轻微物理厚度和稳定投影；内容在后方属于调查现场 |
| 前景 | 调查选择、状态、操作、输入和展开阅读 | 稳定的透明 HUD，跟随视口而非跟随卡片倾斜；不能被模型遮挡 |

建议将现有 16.2 × 9.4 的竖向白板装置调整为接近 1.9:1 的横向研究面，先以约 17.5 × 9.2 世界单位试构图。此数值是原型起点，最终按镜头投影、可读性与模型碰撞检查确定。

板面采用浅暖白、低反射材质；上沿细金属线、短角标和小型固定件提供实体感。正视图中不再让大铭牌、粉笔盒和厚重下沿占据内容面积。标题与工具入口归到前方操作层。

不采用整块真实折射玻璃来承载文字。悬浮感通过前后位置、少量半透明边缘、纸片影子和稳定的镜头视差表达。正式 3D 实现仍需模型深度与文字遮挡规则；本交互样稿只示意这些层级。

### 镜头

进入线索板时以略带侧向视差的正视构图为主；正文与短标题尽量接近屏幕正面。实体侧边可以体现厚度，纸片的阅读区域不使用明显透视变形。

中央报告占板面宽度约三分之一。线索簇分布在左右及上下，外围档案不进入报告文字区。预留的空间不能通过模糊正文或提高雾强度来实现。

检索阵列、线索板、档案收录架维持直接跳转。各场景间镜头以当前位姿为起点到目标位姿，不人为插入另一场景的到达状态。

## 3. 画面排列

```text
RHINE LAB                          01 检索阵列   02 线索板   03 档案收录架

INVESTIGATION / 调查事项
01 黑蛇与塔露拉的赌注 ⌄                              调查已整理
────────────────────────────────────────────────────────────
本次状态 / 正在调用的工具或近期更新

       原文短笺            人物关系签               研究判断

                         调查报告
                        标题与摘要
                       阅读全文 / 版本

       时间条             对照与反证                未解问题

────────────────────────────────────────────────────────────
线索数 / 关联资料数 / 线索目录               继续调查的输入入口
```

这是空间组织，不是固定填满的六宫格。每类线索有自己的尺寸与位置节奏，部分区域可以留空。新调查不能预先铺满示例纸片。

**顶部只回答“现在是哪项调查”。** 下拉入口显示当前会话中的调查板，条目包含标题、状态和最后更新；不把所有板都平铺成主导航按钮。

**中部只回答“知道什么，还差什么”。** 中央始终保留报告位置；原文、判断、时间、疑点有清楚区别，连线只说明确实存在的关系。

**底部承担继续操作。** 线索目录用于访问折叠内容；输入入口用于追问或开始新目标。普通问题的调查归属由 LLM 判断，用户显式点“在此板继续”时可指定归属。

## 4. 卡片系统

普通线索的默认宽高先缩到旧普通卡片约 70%–75%。重新编排标题与短句，不直接把旧卡片及其所有文字整体缩放。

| 类型 | 默认形态 | 板面显示 | 展开后显示 |
| --- | --- | --- | --- |
| 原文摘录 | 暖白短纸、轻纸边、小胶带 | 一段短引文、出处缩写 | 原文上下文、定位、说话人、实际返回范围 |
| 研究判断 | 横索引卡、细橄榄色标记 | 一个判断句、依据数量 | 简短解释、关联证据、推断与不确定性 |
| 时间节点 | 细长纸条、强调时间或先后 | 时间/顺序 + 事件短语 | 时间依据、前后节点及不确定日期 |
| 人物/事件关系 | 双端关系签 | 两个对象 + 关系短语 | 多个来源、关系发生变化的语境 |
| 未解问题 | 淡灰描图纸、轻问号标记 | 一个明确问题 | 尚缺哪类证据、建议继续核对的方向 |
| 矛盾/反证 | 横向双栏、局部暗红标记 | 两条需要比较的依据 | 原文差异、判断修订、撤回历史 |

款式变化来自结构，而不只是换背景色。每类再保留 2–3 个受控变体：固定件位置、纸边、编号位置、轻微倾角。相邻同类卡优先使用不同变体，已有卡片不随刷新换款。

Agent 选择内容类型和重要程度；程序决定具体样式和布局。用户调整过的卡片保留其位置、大小与样式。

### 字体与颜色

- 标题以现有 MiSans 为主；原文摘录可以使用清楚的宋体风格，形成“引文”和“研究判断”的区别。
- 普通卡片以短标题、1–3 行核心内容、1 行来源为限。长标题进入详情，并保留完整的可访问名称。
- 在设计样稿约 1024px 宽的展示条件下，普通标题约 16–19px、正文 12–14px、次要标记不低于 11px；正式桌面按实际投影验证，不能只验纹理字号。
- 墨色 `#252823`；次要字 `#666a5e`；暖白纸 `#F5F2E9`；橄榄色 `#60694D`；黄铜色 `#9A845D`；反证暗红 `#94584D`。
- 色彩不是唯一信息通道。类别、来源状态和未解决问题都有文本标签。

### 默认尺寸原型

普通短笺约 2.0–2.2 × 1.2–1.5；时间条约 2.5 × 0.65–0.8；关系签约 2.8 × 0.85；对照卡约 3.0 × 1.15；中央报告约 4.4 × 3.2 世界单位。这里的数字用于初始排布，不能取代默认镜头下的中文可读性检查。

## 5. 中央报告的状态

| 调查状态 | 中央视觉与文案 | 可用操作 |
| --- | --- | --- |
| 尚未开始 | “从一个问题，开始整理。”；周围空白 | 输入调查问题 |
| 首次调查中 | 调查目标、正在积累的要点；不出现虚假的完成百分比 | 查看当前线索、停止本次执行 |
| 已有报告，继续补证 | 保留上一版标题；提示“正在补充依据” | 阅读上一版报告、查看新线索 |
| 新线索已写入，尚未发新版 | 标记“有新线索，报告待更新” | 旧报告仍可读，新增内容可定位 |
| 报告已发布 | 标题、短摘要、报告版本与阅读入口 | 阅读报告、查看旧版、继续调查 |
| 中途暂停或失败 | 明确本次执行未完成；已有线索与报告保留 | 继续、核对错误、阅读已保存内容 |

报告摘要在默认板面控制为 2–4 行。完整报告进入阅读层，保留引用跳转和版本选择。中央报告不是最后一条聊天消息的镜像，而是属于该板的持久报告对象。

成功发布与 Agent 运行状态分开判断：发布后执行被打断，已保存的报告仍可读；发布前被打断，不伪装成调查完成。

## 6. 交互细节

### 6.1 多板切换

点击调查标题展开目录。切换查看板只更换板上内容，保留场景、镜头与当前世界坐标。目录不自动收走旧板的数据。

查看板与 Agent 工作板是不同状态。用户查看旧板期间，Agent 在另一板更新，顶部显示“另一项调查新增 2 条线索”，提供返回入口；不跳镜头、不替换当前报告。

新问题提交后，由 LLM 结合目标与历史摘要选择新建、沿用或恢复。将结果以一句短状态反馈给用户，例如“继续：黑蛇与塔露拉的赌注”。不要弹出一个每轮必选的板归属确认框。

### 6.2 线索详情

点击卡片，卡片保持原位，并用细轮廓提示选中。前方打开与其关联的阅读层，显示完整内容、来源和关系；背景减少对比，维持研究现场的可见性。

详情正文需要一层浅暖白的阅读底，保证长文本可读；其范围只覆盖阅读区域。四周的操作层继续透明。没有需要展开的内容时，不额外堆叠浮窗。

关闭回到原板、原镜头和原选择位置。Escape 可收起；焦点返回刚才的卡片。窄窗口将详情变成当前内容区域，避免左右挤压。

### 6.3 原文与版本

从线索进入原文，保留“返回这条线索”的路径。标清它是搜索摘要、实际读到的正文还是截断正文；原文无法重取时仍保留当时短摘录与来源信息。

报告版本选择只改变当前阅读的报告，不回滚板面线索。旧版标明版本和形成时点，最新版与新增证据之间的关系清楚可见。

### 6.4 更新和去重

同一判断获得新来源时，更新原卡的依据数量与详情，轻微提示补证。不同判断允许来自同一篇资料。内容归并由 LLM 决定，重试重复提交由工具保证幂等。

新的独立线索放在相关簇的空位；没有空位时进入该簇的折叠内容，不推动用户正在读的卡片。用户手动拖动后，布局器不重新安排它。

连线默认显示少量主要关系。选中时突出支持、反证、先后关系，其他连线减弱。关系标签在聚焦时显示，不把整板变成密集的交叉线网。

## 7. 动画规则

时长为原型目标，正式实现按帧耗时与实际观感调整。

| 动作 | 建议运动 | 建议时长 |
| --- | --- | --- |
| 首次进入板场景 | 连续镜头进入；操作层在视角稳定后建立 | 约 550–750ms |
| 切换调查板 | 同一板面中，旧内容轻退、新内容短距离落位；不移动整个场景 | 约 220–320ms |
| 新线索 | 从目标位上方约 12–18 屏幕像素落入，极轻的深度变化 | 约 240–320ms |
| 已有线索补证 | 原卡不移动；状态/来源标记短暂强调 | 约 500–650ms |
| 建立关系 | 两端确定后出现连接，不能提前连到不存在的卡片 | 约 140–200ms |
| 打开详情或报告 | 阅读层小幅接近用户，背景对比降低 | 约 180–240ms |
| 发布报告 | 中央原位更新标题、摘要和版本；周围线索不重排 | 约 220–300ms |
| 恢复历史、断线重连 | 直接恢复最新快照，不逐条播放历史新增 | 无入场队列 |

新状态可以打断尚未完成的过渡，运动从当前可见位置继续，不能先回初始姿态再播放。减少动态效果设置下用直接替换和必要的状态标记。无循环漂浮、持续闪烁和装饰性扫描线。

本样稿演示新线索落位、卡片补证标记和场景构图对比；正式镜头轨迹、实体深度遮挡及所有动画打断组合需要在 Three.js 场景中实现和测试。

## 8. 容量、窄窗口与性能

首轮实现以 12 张主线索和一份中央报告作为可见预算，再根据当前性能档实测决定是否扩到 16 张。数据层保存所有线索；线索目录、主题折叠和聚焦解决展示容量，不能按 12 条截断保存。

场景只实例化当前板及其可见卡片。更换单条内容只更新该卡纹理和受影响连线；拖动只更新位置，不重新生成全部文字。保持已有的绘制清晰度策略，纸片无需新增高面数模型。

桌面宽视口保留空间式排布。窄窗口中报告先行、线索改为两列；更窄时改一列，隐藏跨列连接线，详情仍能查看关系。保留全部内容和入口，不继续压小中文字体。

主画面不出现一条占据中央的原生粗滚动条。正式应用仅让展开后的长正文拥有局部滚动；滚动条细、低对比，滚动与悬停时提示位置，并提供键盘操作。窄屏整页纵向阅读属于正常响应式布局。

后续板旁资料区可以占用扩展视角中的右侧空间，但本阶段不显示空壳栏目。档案架的“Agent 已读”和用户手动收录仍需要独立的来源标记，不与线索的成立状态混为一谈。

## 9. Agent 能力如何映射到画面

| 持久操作 | 画面变化 | 保持稳定的部分 |
| --- | --- | --- |
| `investigation_open` 新建 | 建立空板与调查目标，目录增加一项 | 全局场景导航与输入位置 |
| `investigation_open` 恢复 | 对应调查进入工作状态 | 用户当前查看的板，除非用户主动跟随 |
| `investigation_update` 新增 | 对应簇增加短线索、更新数量 | 已有卡的位置、中央报告的位置 |
| `investigation_update` 补证 | 原卡依据更新，必要时报告标记待更新 | 卡片身份和用户布局 |
| `investigation_update` 撤回 | 保留可追溯的撤回状态与反证关联 | 旧报告引用仍能找到当时内容 |
| `investigation_publish` | 中央出现新报告版本与阅读入口 | 历史报告、周围线索、当前用户视角 |

Skill 的判定、存储一致性、作用域、版本和幂等规则沿用第一阶段调研方案。画面根据真实工具提交结果更新，不从“正在分析”一类自然语言状态推测已经新增了线索。

## 10. 样稿覆盖与交付边界

交互样稿支持：

- 切换示例调查板；查看板与工作板分离提示。
- 六种线索款式、线索详情、来源阅读层与线索目录。
- 中央报告与历史版本切换。
- 输入后演示继续调查、补充线索和空板开始调查。
- 通过设计调节项比较完成/查阅/空白/暂停状态、两种档案距离与两种卡片排版。
- 桌面和窄窗口下的内容重排。

样稿中的剧情内容、数量、工具活动与报告都是明确标记的交互示例；没有调用模型、联网查证或生成实际调查结论。它不展示 LLM 归属判断的准确率，不代表正式 3D 场景已完成。

**实施顺序：** 先在实际场景验证研究面与短卡的默认可读性；再接通持久化、四个工具和 skill；随后接入实时增量、报告与多板；最后核对镜头、遮挡、打断和测试发行版。

通过条件：在用户当前性能档下，一眼能找到调查目标和报告；能分清原文、判断、疑点；追问保持调查连续；新线索确实逐步出现；历史板、用户布局和原文引用都可恢复。
