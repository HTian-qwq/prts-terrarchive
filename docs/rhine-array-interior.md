# 阵列内构贴图与抽取实体：第一版

2026-09-11。用户确认：下部复杂内构以贴图代替，档案抽出时再使用实体。此次实现仅优化阵列的内构，保留原始 GLB、外壳、顶边、侧面、运动规则及既有画质。

> 本文数据固定于第一阶段验证构建。后续已恢复原品牌名牌、移除额外标签深度通道、统一清晰盖板，并继续实施 [实例剔除与阴影复用](rhine-array-visibility.md)。下列帧提交量用于记录当时前后对照，不是最新构建的测量值。

## 实现

- `ui/rhine/original/array-interior.ts` 从当前 GLB 和运行时材质一次离屏生成线性 HDR 图。无需额外模型下载，每次场景创建只生成一次，全阵列共享。
- `Internal_Ceramic`、`Subsurface_Optics`、`Optical_Edges` 原为每份 19,356 三角形；内部烘焙至原基板正面上的 2 三角代理，盖板外的 1,928 三角细字继续保留实体。三组替换后合计 1,930 三角形。
- 代理使用基板原有正面轮廓并位于玻璃之后，进入不透明队列供透射捕获。原基板继续提供背面、倒角与投影。主场景 SSAO、景深和标签遮挡深度读取同一代理表面，不使用 fragment 遮罩隐藏高模。
- 共享图为 1024×740、RGBA HalfFloat，基础像素占 6,062,080 字节，含 mip 链的 GPU 纹理数据理论量 8,081,944 字节（约 7.71 MiB）；另保留基础像素用于上下文恢复。捕获用 RenderTarget 在读回后立即释放。
- 保留原高低材质注册；选中、归位副本、Agent 占位仍沿用原有单一实体所有权。选中时阵列代理隐藏，完整单体在抬起前接管；归位结束后恢复代理。没有把代理加入完整单体，资料架与拆解模型保留全部几何。
- 读取半浮点图失败、输出异常或设备不支持时回退完整阵列。退出时释放代理、共享贴图与原资源。各向异性质量控制继续生效。

重新加载页面后默认启用。`?rhineArray=geometry` 可在同一构建内使用原始阵列对照；已有查询参数时使用 `&rhineArray=geometry`。该开关不改变用户已保存画质。

## 验证

TypeScript 检查、生产构建和四个相关测试文件通过。新增测试读取真实 GLB，检查几何分离、基板代理边界、UV、共享资源所有权、渲染状态恢复和失败读回清理。顺带将旧分页测试中已经过时的八槽断言对齐当前十二槽约定，未修改分页实现。

浏览器对照使用独立预览、Chromium / SwiftShader、960×540 CSS 视口、1920×1080 最终输出。画质保持景深 100、32 样本 AO、2048 阴影、SMAA、透射比例 1。选择真实目录的同一档案，固定相机与运动状态后采集。

为缩短软件渲染等待，测试工具只在中间收束帧屏蔽 GL draw 调用，固定推进状态；截图与计数来自恢复后的至少三次完整实际绘制。该方法用于正确性与提交量对照，不能推算 FPS。

## 当前边界

烘焙固定了内构的观察方向和光照，动态阴影以保守的 0.3 强度乘回，因此阵列内构是近似表达。玻璃外壳仍实时渲染。固定状态对照不代替真机全速检查初升、落回与斜视的过渡观感。

此次没有实现按露出高度截短外壳、逐实例遮挡剔除、远景独立材质或档案架贴图分级。用户提出的“只保留露出的上部”仍可进一步用于外壳；当前优先去掉被重复绘制的复杂内构。原模型和源 Blender 工程保持不变。

截图、测量与复跑工具见 `verification/rhine-array-interior/`。
