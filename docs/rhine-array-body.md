# 阵列主体分区、细字预烘焙与螺丝 LOD

2026-09-12。本轮基线为 [部件遮挡剔除](rhine-array-occlusion.md) 完成后的插件：固定阵列整帧提交 1,516,950 个三角形。不是 RhineLabUI 原版，也不是最初未做内构贴图的插件。

## 实现范围

`array-shell.ts` 把盖板和边框各分成五个共享实例批次：四个区域保留各处的倒角细面，跨越区域边界的原三角形放在一个跨区批次中。没有切割、补面、移动顶点或重算法线；原来的每个三角形恰好进入一个批次。这样既能剔除被挡住的下方边角，也不会因统一裁掉某一高度以下的几何而露洞。

各区域沿用上一轮的当帧视锥及保守遮挡证明。邻居移动、镜头改变、抽出或归位后，新露出的区域在提交前重新判定。只能部分证明遮挡的区域仍保留，包括跨区的大面。透明盖板不会充当遮挡物；不透明基板继续保留原投影通道。

点选入口现在查询全部盖板区域，再通过实例索引映射到逻辑档案。原单一盖板入口已替换，避免只有某个角能点中。抽出、归位的完整模型以及架上主体材质不参与这次分区。

## 细节与贴图

- 细字从每份 1,928 个三角形变为一个双三角形平面，采用原几何烘焙的法线／覆盖率贴图，仍使用原材质参数和实时光照。按投影尺寸切换：低于约 64 像素进入贴图，大于约 72 像素恢复实体，保留滞回以减少临界位置跳变。
- 512×64 RGBA 数据只有一份，所有阵列细字共享。基础像素 128 KiB，连同 mipmaps 约 171 KiB；CPU 保留 128 KiB 像素供 WebGL 上下文恢复。RLE 编码随生产包加载，不增加网络请求。
- `npm run build:rhine` 先运行 `bake:rhine-details`。预烘焙数据通过三角形位置和法线签名绑定当前 GLB 与运行时变换；资源变了、签名不匹配时保留实体。浏览器只解码数据，不做运行时栅格烘焙或 GPU 读回。
- 螺丝凹槽贴图试验会丢失斜视刻纹，最终没有启用。凹槽和刻纹保持原三角形，只将小尺寸螺丝外圈的角度量化从 24 档改为 16 档。投影尺寸放大后仍恢复原始高模；真实资产的轮廓与表面射线检查继续通过。

| 检查视角 | 本轮之前 | 本轮之后 | 减少 | draw calls 前 → 后 |

| 初始阵列 | 1,516,950 | 879,480 | 42.02% | 57 → 73 |
| 连续滚动三项后 | 1,530,978 | 888,840 | 41.94% | 59 → 75 |
| 切换列后 | 1,507,950 | 878,230 | 41.76% | 57 → 73 |
| 档案架及背景阵列 | 1,107,856 | 920,894 | 16.88% | 438 → 454 |
| 抽出近景 | 1,107,258 | 1,107,258 | 0% | 275 → 275 |
| 竖屏档案架 | 870,072 | 811,972 | 6.68% | 438 → 454 |

这些是整帧累计三角形提交数，包含多个渲染通道。初始阵列仍有 166 个完整盒子进入视锥，但盖板下方两个区域分别只保留 10、12 个实例，边框下方两个区域分别保留 12、14 个。共有 531 个区域／细节实例因遮挡被省去，另有 571 个因画外被省去；84 份剩余细字使用贴图。区域数量不能解释为省掉同样数量的整盒。

分区增加 16 次绘制调用和可见性计算。已将遮挡证明中重复的八角点投影改为包围盒对平面的支撑范围计算，并保留近裁面与边缘余量。10 个记录视角、共 54,530 组区域／槽位的前后算法判定一致，真实射线测试继续通过。

用记录的实际矩阵和几何包围盒进行 Node/V8 局部 CPU 基准，预热 200 次、测量 1,000 次：

| 布局 | 本轮之前中位数 | 本轮之后中位数 | 增量 |
| --- | ---: | ---: | ---: |
| 阵列提交逻辑 | 0.384 ms | 1.065 ms | 约 0.681 ms |
| 档案架视角的背景阵列 | 0.134 ms | 0.316 ms | 约 0.182 ms |

这只度量视锥、LOD、遮挡和矩阵压缩，不包含真实 GL 绘制或浏览器整帧。模型和几何仍常驻复用，也没有压缩原 GLB。需要在实际显卡上确认帧率收益，不能把上述 42% 直接当成 FPS 增长。

## 验证口径

数据和脚本见 [验证目录](verification/rhine-array-body/)，截图仅在本地生成。固定性能档、1920×1080、DPR 1，使用相同 12 份资料；另测 900×1200 竖屏。相同虚拟动画时刻推进后，每个端点实际绘制三帧。浏览器为 SwiftShader，不能把三角形下降直接换算成真实 GPU 帧率提升。

新测试验证分区前后完整三角形／属性集合一致、多个斜视方向的真实射线命中一致、分区压缩与槽位替换后点选仍指向正确档案，以及预烘焙数据与当前 GLB、法线、覆盖率相符。既有阴影、遮挡恢复、完整模型复用、原版运动等相关检查继续通过。

40 个相关用例通过，预烘焙、TypeScript 检查及生产构建通过。浏览器检查 10 个视角与 300 个聚焦、抽出、归位运动状态；运动时保持完整实体，没有因切换表示重复创建模型。中间运动帧检查的是状态，截图检查的是各端点，不声称全部中间帧都做了像素对照。

仅主体分区的初始阵列对照，在排除页脚时钟后只有 27 个 RGB 像素不同；最终方案另外包含细字贴图和螺丝外圈 LOD，允许细节处出现像素差异。放大检查保留了螺丝刻纹与盒体形状，没有发现成片缺边；不将最终画面描述为逐像素完全相同。完整差异指标保留在验证目录。

最终初始阵列中，排除时钟后有 5,939 个像素变化（约占画面 0.286%），其中 333 个像素的通道差值超过 8/255，最大单通道差值 98/255；因此平均差值不能代替对局部细节的检查。抽出近景排除时钟后逐像素一致。可查看 [完整统计](verification/rhine-array-body/comparison.json)。

新增 URL 比较开关：`rhineShell=off` 关闭主体分区，`rhineDetails=off` 关闭细字贴图。`rhineLod=off` 关闭所有细节 LOD；`rhineOcclusion=off` 同时关闭动态遮挡与依赖它的主体分区。基线中已有的内构贴图不受这些新增开关影响。

这些开关用于定位差异；完全重现本轮之前的画面应使用验证目录的基线包，因为螺丝低模也已调整。`rhineWorkbench.stats().arrayDetails` 可确认实际使用的贴图数量与资源签名。
