# 阵列部件的动态遮挡与视锥剔除

2026-09-12。在 [静止档案贴图与细节 LOD](rhine-static-lod.md) 之后继续降低阵列绘制量。此轮基线已包含内构贴图、螺丝 LOD 和架上静止贴图；下述收益只与这个基线比较。

后续已加入盖板／边框分区与细字预烘焙，见 [阵列主体优化](rhine-array-body.md)。本页保留第一轮部件剔除的数据。

## 本轮实现

阵列保留完整盒子的视锥剔除、实例压缩与螺丝 LOD，再对下方螺丝和立体文字做部件级剔除。上下螺丝各自使用独立的实例批次，原顶面、边框、盖板及细节坐标没有修改。某个盒子还在屏幕内时，其已经出画面的下方螺丝、文字也可以从提交列表排除。

遮挡物只采用 `Optical_Diffuser` 的真实不透明矩形正面。初始化确认其由两块共享对角线的三角形覆盖完整矩形；不使用透明盖板或整盒包围盒作为遮挡物。资产不符合条件时停用这一遮挡判断。

每帧根据最终镜头与当帧档案姿态更新遮挡区域，用平面前后关系及四个边界平面证明部件的整个包围盒都在基板后方。部件还需留出至少 0.08 世界单位或约三输出像素的余量，保护斜视、反锯齿及薄盖板的透射边缘。无法证明整件被挡住就保留它；多个不完整遮挡物不会凭少数采样点拼成“完全遮挡”的结论。

选中、抽出、归位副本和 Agent 占用的槽位先按既有所有权逻辑从普通阵列移除。遮挡列表随之更新，邻居移走、抬高或镜头改变时，当帧恢复新露出的部件。几何常驻，只修改有效实例和矩阵上传范围，不会在滚动中卸载、重新创建模型。

部件画外剔除保留原 0.35 世界单位余量。原外壳仍提供鼠标拾取面，压缩后的实例索引仍映射回逻辑档案。所有有效投影基板继续留在阴影通道，包括画面外的基板，避免因为主相机看不见就删掉其阴影。

## 实际提交量

4177 本地预览，固定性能档、12 份资料、1920×1080；竖屏一项为 900×1200。以下是 WebGLRenderer 统计的整帧三角形提交量，包含透射等多个绘制通道，不是资产自身的唯一面数。

| 检查视角 | 修改前 | 修改后 | 减少 | draw calls 前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 初始阵列 | 2,049,174 | 1,516,950 | 25.97% | 55 → 57 |
| 连续滚动三项后 | 2,077,466 | 1,530,978 | 26.31% | 57 → 59 |
| 切换列后 | 2,038,798 | 1,507,950 | 26.04% | 55 → 57 |
| 档案架及背景阵列 | 1,265,072 | 1,107,856 | 12.43% | 436 → 438 |
| 抽出近景 | 1,107,258 | 1,107,258 | 0% | 275 → 275 |
| 竖屏档案架 | 922,664 | 870,072 | 5.70% | 436 → 438 |

初始阵列中，完整盒子仍有 166 个进入主相机视锥、287 个基板保留投影。进一步省去 124 个完全遮挡的部件实例和 115 个画面外的部件实例；下方螺丝从 166 个降到 9 个，立体文字从 166 份降到 84 份。这里的“部件”不等于整盒。

两组记录的镜头和档案位置相同。排除页脚时钟后，初始阵列、抽出、返回阵列、跨列、竖屏截图 RGB 相同；滚动截图只有 3 个像素出现最多 1/255 的通道差异。档案架主体区域一致，其画面底部在部分状态存在最多 1/255 的色阶差异。没有将这些截图描述成所有动画中间帧都完全一致；详见 [完整像素统计](verification/rhine-array-occlusion/comparison.json)。

## CPU 开销控制

先用现有整盒视锥列表缩小遮挡物范围，再用 16×16 屏幕网格寻找可能挡住某部件的基板，最后执行完整几何证明。网格和压缩列表预先分配为 TypedArray。只针对下方螺丝与密集文字进行检查；顶部螺丝、装饰片通常露出，逐个检查节省的几何少，故保持原来的提交策略。

用记录的真实阵列矩阵做静态 CPU 微基准，恢复记录中的 LOD 滞回状态；每项预热 200 次、测量 1,000 次。记录中的几何包围盒以盒体代理，只测视锥、LOD、遮挡及矩阵压缩，不执行 GL 绘制：

| 布局 | 修改前提交逻辑中位耗时 | 修改后 | 增量 |
| --- | ---: | ---: | ---: |
| 阵列 | 0.097 ms | 0.384 ms | 约 0.287 ms |
| 档案架视角的背景阵列 | 0.071 ms | 0.135 ms | 约 0.064 ms |

这是本机 Node/V8 的局部 CPU 检查，不代表浏览器整帧耗时或显卡收益。拆分螺丝批次会增加少量 draw calls，不能只根据三角形减少推算 FPS；仍需在实际设备上观察帧时间。

## 验证和边界

相关测试覆盖正交／透视镜头、斜视与旋转包围盒、邻居移除／抬高后的即时恢复、近裁面、边缘露出、非法遮挡矩形、部件出入画面、实际射线命中、拾取映射及阴影保留。真实 GLB 的螺丝拆分前后总面数不变，原低模浮雕检查继续通过。

7 个相关测试文件、34 个用例通过，TypeScript 检查和生产构建通过。浏览器检查了 10 个状态，无页面或控制台错误；抽出、归位的连续状态仍使用完整内构，复用已有模型，停止运动后恢复架上贴图。

截图与原始统计见 [验证目录](verification/rhine-array-occlusion/)。浏览器采用 SwiftShader，推进中间动画状态后，每个检查状态实际绘制三帧采集。它验证端点外观及提交状态，不作为真实 GPU 帧率测量，也不代表所有中间帧都已截图检查。

本轮生产 `lib/rhine/rhine.js` 为 1,024,028 字节，SHA-256 为 `7df7dc2b02d3c0b9837a51cce4652c7d5908a975f1064668ff5cdc665a3844e5`，与浏览器实际加载记录一致。4177 读取这份产物；插件本地三处 DSH 安装路径均链接到同一插件目录，已打开页面需刷新以加载新脚本。

这是部件级动态遮挡剔除，没有统一截掉盒子下半部；透明盖板、边框等主体仍保留。文字尚未进一步改为独立细节贴图，也没有新增远景整排图片替身。

URL 加入 `rhineOcclusion=off` 可回到本轮之前的整盒列表与合并螺丝批次，关闭新加的部件剔除；已有阵列内构贴图、螺丝 LOD、架上贴图仍保留。`rhineWorkbench.stats().arrayVisibility.occlusion` 提供遮挡剔除数 `culledParts`、部件画外剔除数 `outsideParts`、每个批次的保留数及单通道省下的三角形数。
