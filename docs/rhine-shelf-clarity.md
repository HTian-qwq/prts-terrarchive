# 档案架清晰度

2026-09-12。继阵列边缘修复后，用户反馈档案架中的盒体和内构仍显模糊。本轮沿用性能档进行固定视角对照。

## 诊断

架上十二份档案一直使用完整模型，原品牌名牌贴图为每份独立的 1024×440 Canvas；外壳清晰度为 1，着色器盖板粗糙度为 0.025。没有把架上内构替换为阵列烘焙图，也没有重新启用磨砂动画。

性能档虽然主画面已为 100%／SMAA，但透射比例仍为 0.5：玻璃后面的内构先进入半宽、半高的透射捕获，再被盖板采样。用同相机对照以下三种设置：

| 配置 | 主画面缓冲 | 透射比例 | 绘制调用 | 各通道三角形提交 |
| --- | --- | ---: | ---: | ---: |
| 修改前性能档 | 1920×1080 | 50% | 546 | 2,736,064 |
| 仅提高透射 | 1920×1080 | 100% | 546 | 2,736,064 |
| 仅提高主渲染比例 | 2400×1350 | 50% | 546 | 2,736,064 |

目视对照中，提高透射比例明显改善圆环、线路和内侧细节；单纯把主画面提高至 125% 的改善较小。因此采用第二项，保持主渲染比例。外框和外侧名牌仍受主画面像素预算影响，透射修改不能消除所有边缘采样限制。

性能档本身已关闭景深，不能把上述性能档模糊归因于景深。其他档位的景深会让十二份档案的前后部分落在焦外，因此同时让档案架视图保持无景深虚化。

## 实现

- adapter 分别保留用户配置和实际配置。目标位置为档案架时，实际透射为 1、景深为 0，其余参数保持用户选择。
- 进入／离开档案架、用户调整画质时一次应用配置；不随相机位移逐帧插值缓冲尺寸。原场景的相同配置去重继续生效。
- 返回阵列恢复用户配置。架上修改设置会正常保存，返回阵列后按新请求值生效；窗口 resize 保持架上实际参数。独立查看器继续使用用户配置。
- `stats().renderQuality` 报实际参数，`requestedQuality` 和工作台的 `quality` 报用户配置。设置说明注明透射与景深的阵列／档案架差异。

透射设置属于整个 renderer。在相机过渡时，同时入镜的背景阵列也会使用目标视图的配置，并非逐盒独立的透射缓冲。

## 成本与验证

从半宽半高改为全分辨率，使透射捕获的理论像素量增加四倍；模型几何、主画面分辨率和性能档的绘制调用没有增加。其他原本启用景深的档位，在架上会省去景深的深度绘制与合成。本轮未测硬件 GPU 帧率，不能据此推算 FPS。

对照使用本机 Chromium／SwiftShader、1920×1080、DPR 1、十二份真实来源的隔离浏览器快照。跳过初始化中间 GL draw，同一姿态端点真实绘制三帧。原图及浏览器原生裁剪图都保留；未修改模型图片。软件渲染器的 JavaScript 和截图等待计时不是硬件 GPU 帧时间。

TypeScript、生产构建及原版行为、客户端、模型池三组相关测试通过。浏览器前后对照和实际设置／视图往返检查见 [验证目录](verification/rhine-shelf-clarity/)。

最终浏览器检查通过：架上改变请求透射至 25%、景深至 100% 后，架上实际仍为 100%／0%；窗口缩放后保持；回到阵列恢复请求值。恢复性能配置后实际绘制阵列和档案架往返端点，十二份档案身份一致，模型创建计数未增加，无页面或 console 错误。首次架上端点的相机、档案姿态、主缓冲尺寸和绘制量与基线相同。4177 与本地三个 DSH 链接使用同一产物。
