# 检索期间新资料与抽取瞬时卡顿

2026-09-12。用户明确卡顿发生在新资料出现、模型抽出时，表现为突然停顿。

## 定位

前一轮的内构贴图、实例剔除和阴影复用已经生效。本轮基线脚本为 `673e6b695514d21269c0a852bdaa24b0437593b78bb09fe85489ce1d8c901ed0`。

浏览器重放真实目录中的十二份资料，在首次到达的同步 `update` 中测到 42.2 ms，并新增十二个 Group、204 个 Mesh、192 个材质、十二张 CanvasTexture，重画十二次原品牌名牌。模型几何本身共享，但材质、对象树和标签仍集中分配。自动选档的归位副本、读取和送往档案架的活动模型也在动画回调中临时创建；屏蔽中间 GL draw 后仍观察到约 23–30 ms 的 JavaScript 帧尖峰。

相同资料快照重复四十次，中位同步更新为 0.65 ms，模型、材质、Canvas 与标签重画新增数都为零。动态过程未新增 shader program 或编译，不能将此次尖峰归因于着色器编译。GPU 纹理上传耗时未单独隔离。

上述计时来自本机 Chromium / SwiftShader，并包含诊断计数开销；它用于定位集中分配，不能代表硬件 GPU 帧率。

## 修改

- 保留所有资料和 operation 状态的立即处理。架上三维模型放入有键的准备队列，每个动画帧之后的任务中最多准备一份，同时初始化其标签纹理，避免首次进入镜头时集中上传。
- 切页、删除资料、切会话取消过期准备项。任务执行时取最新资料；选中的待办优先准备。延迟建模不把本轮新资料提前标记为运输完成，抽取、停留和归位仍完整执行。
- 启动时逐帧准备三个可用的完整活动模型。活动与归位共用同一个缓存，最多保留四份；架上缓存单独最多十二份，材质不会与活动模型混用。
- 每份缓存模型保留独立材质、uniform 与 CanvasTexture，只在编号改变时重画。旧来源标记在回收时清除，几何继续共享；退出时释放缓存材质及纹理。
- 主模型编号未改变时省去重复重画，字体加载状态改变仍允许刷新。盖板粗糙度、原品牌名牌、模型精度和画质参数保持现状。

缓存用少量常驻材质与标签纹理换取较少的动画期分配；不复制完整 GLB 几何。资料列表不等待三维模型准备完成。

## 验证结果

修复构建 `lib/rhine/rhine.js`：1,014,810 字节，SHA256 `be0b1e2d00fa3b7008f46adc12503272c6b7a06b93dd2b96f1a7c8f6877957a6`。4177 与当前 DSH 插件链接读取相同构建，需整页刷新加载。

同流程复跑，十二份资料到达的同步更新 **42.2 → 8.3 ms**，该回调内新增模型组、Mesh、材质、Canvas 和标签重画均为 **0**。十二份架上模型在第 110–121 帧分别准备，每帧一份，每项 **2.4–3.7 ms**。

完整过程累计创建十五份模型，全部对应三个启动预备和十二个架上准备任务；检索、读取和归位动画回调内没有新增模型克隆，共复用七次，结束时恢复三个移动备用。前后抽样的活动实体、归位副本及三角形提交相同，到达、读取、运输与归位仍执行。最终架上十二份全部可见，真实 sourceId 与 NO.001–NO.012 对应，各 Canvas 的原品牌字段逐个检查通过。

Rhine TypeScript、生产构建以及七个相关测试文件通过。新增准备队列的七个用例检查逐帧串行、替换、优先级、取消、暂停、异步失败和销毁；模型池的六个用例调用真实 Three / ArchiveScene / CardAppearance 方法，检查独立编号与 uniform、材质隔离、池上限、共享几何所有权、归位姿态和最终释放。

浏览器没有页面或 console 错误。每种构建只进行了一次固定流程诊断，不能把小幅计时差异当成稳定加速比；屏蔽 GL draw 的中间帧也不能代表真实 GPU 帧时间。
