# 阵列实例剔除与阴影复用：第二阶段

2026-09-11。基于已经启用内构烘焙、原品牌名牌、清晰盖板粗糙度 0.025 的构建继续优化。

> 本文保留第二阶段的构建与对照数据。2026-09-12 针对新资料到达及抽出时的瞬时卡顿继续加入分帧准备与模型复用，见 [检索卡顿记录](rhine-search-stutter.md)。

## 当前实现

- 第一阶段的共享内构图仍生效：每份阵列 23,556 → 6,130 三角形，选中与抽出改用原完整实体。贴图为场景加载时烘焙的 1024×740 HDR 图，不是离线 AO / 法线 / ORM 资产。
- `array-visibility.ts` 将 288 个逻辑槽位及其真实姿态与 GPU 提交列表分开。已被选中、归位副本、Agent 占用的槽位，以及原动画窗口外的槽位，直接从提交列表排除，不再用零缩放隐藏高模。
- 使用当前帧最终相机、完整卡体包围盒、波浪转角及 0.35 世界单位的保守余量做视锥剔除。全部非投影外壳与烘焙内构使用同一可见列表，防止盖板和内部切换不同步。
- 唯一投影的阵列基板 `Optical_Diffuser` 继续提交所有有效槽位，包含画面外可能投下阴影的卡片。没有根据雾化、相邻卡片遮挡或只露出顶部就直接裁掉下半部。
- 压缩后同步 `InstancedMesh.count`、矩阵上传范围及包围体缓存。鼠标拾取将实例编号映射回逻辑槽位；Agent 读取原始姿态，不会把压缩后的数组位置误认为档案身份。
- 阴影在场景运动和架上模型更新后，每个逻辑帧刷新一次。主画面、SSAO、景深继续读取同一份动态阴影；原有画质、阴影分辨率和后处理保留。

## 对照与边界

`?rhineCull=off` 关闭镜头视锥剔除，保留有效槽位压缩和阴影复用。`?rhineArray=geometry` 关闭内构贴图；二者可组合。参数只用于 URL 对照，不改已保存画质。

`rhineWorkbench.stats().arrayVisibility` 提供逻辑容量、有效槽位、可见槽位、剔除槽位、投影槽位和每个批次的 `count`；`archiveCount` 保持逻辑池定义。帧三角形是各通道提交总量，不是唯一模型面数，也不能直接换算 FPS。

尚未实施：按露出高度截短模型、邻卡遮挡剔除、按屏幕尺寸分档的外壳 LOD、档案架低模、离线法线 / AO / ORM 与压缩纹理资产。当前清晰盖板会露出内部，后续截短或简化仍需单独验证斜视与抽取过渡。
