# PRTS 模式的网页搜索与抓取

PRTS 模式使用宿主 DSH 的 `web_search` / `web_fetch`。PRTS 本地语料检索和 `cloud_search` 不使用这两套网页接口。

## 桌面账号登录后，搜索仍提示缺少 API Key

目前核对的 DSH 0.1.7-rc.2 中，聊天的 `deepseek-account` 与默认网页搜索 `deepseek-official` 是两条独立通路。
网页登录成功不代表已配置 DeepSeek 开放平台 API Key。账号登录 token、npm token 都不能代替这个 Key。

在 DSH 的**插件 → 网页搜索**配置页面填写自己的 DeepSeek 开放平台 API Key 并保存；旧版可在**设置 → 模型**中配置相同的 `DEEPSEEK_API_KEY` 凭据。
凭据存入宿主的凭据服务，不应写入 PRTS 插件、发行包或会话消息。已有第三方搜索提供方的用户按该提供方配置，不要为修复缺 Key 随意改写搜索端点。

没有独立 Key 时，当前官方实现无法仅靠桌面账号完成默认网页搜索。PRTS 会提示这个条件，并继续可用的本地检索；这不代表现实资料已经联网核实。

## `web_fetch failed: TypeError: fetch failed`

网页抓取不依赖搜索的 API Key。这个错误只说明那次页面请求没有成功，日志若未记录底层原因，就无法进一步区分 DNS、连接、代理和 TLS 问题。
两个同域名页面失败也不能推导出其他网站全部不可访问。

先确认目标页面在本机网络中是否可访问，再确认 **DSH 进程**使用的网络配置。浏览器代理设置未必会传给 DSH 的 Node Host。
当前官方源码从启动环境读取标准代理变量（如 `HTTPS_PROXY`）；如果确实需要代理，应使用本机实际的 HTTP 代理地址，在启动 DSH 前设置，然后彻底退出并重新启动 DSH。
不要复制不属于自己机器的端口，不要用关闭证书校验来绕过 TLS 故障。旧宿主对代理的具体支持以它自己的版本为准。

插件不会代填密钥、修改系统代理或替换宿主网络实现。新增故障指引会按会话及失败域名记录，成功后移除；不保存凭据、URL 查询参数或请求头。
