# 阵列导航限速

方向键长按与连按、阵列导航按钮、滚轮 / 触控板、触屏滑动、刻度选取和盒子点选共享一套手动导航限制：

- 首次操作立即响应；两次接受的切换至少间隔 **350 ms**。
- 当已有 **3 份完整档案正在回落**时，暂不接受进一步的阵列滑动。只用墙钟间隔无法保证低帧率时的模型数量，因此另检查实际回落数量。
- 被限制的输入立即丢弃，不累积令牌，不保存待执行方向，不在松手后补播。长按期间后续键盘重复事件会在允许时继续推进。
- 标题、编号、选中刻度只跟随实际接受的模型选择更新。被限制的键盘和按钮输入也不再触发多余的阅读器关闭、模型选中清理与 DOM 重绘。
- 显式打开资料和数据同步仍准确定位请求的来源。阅读器、搜索输入和 360° 查看器的按键处理不进入阵列限速；档案架原有导航维持其独立路径。

参数在 `ui/rhine/archive-navigation-limit.ts`。工作台在 WebGL 载入前或不可用时也使用同一个限制器；主场景通过 `RhineSceneOptions.navigationLimiter` 接入，所有受限入口共用预算。

`rhineWorkbench.stats().navigation` 提供 `intervalMs`、`maxReturningFiles`、`accepted`、`rateLimited`、`busyLimited` 和 `queued`。临时性能记录的开始 / 结束 metadata 也包含这些字段，可取差值检查本次测试实际接受和拦截了多少输入。采样期间，每次接受的阵列导航还会留下不含资料 ID 的 `archive-navigation` 事件。

回落数量上限针对手动浏览引入的模型副本；正常阅读、检索资料动画以及数据同步的业务操作不会被丢弃。此更改没有对模型几何、材质、LOD 阈值或回落动画作调整。

验证：

- 四项新增测试：首个输入与冷却边界、30 Hz 连发与改变方向、积压回落保护，以及使用真实回落弹簧公式模拟 5 FPS 渲染与 100 Hz 输入。加上相关回归，共 40 项通过。
- 浏览器检查：混合输入共用冷却；模型和 UI 来源同步；回落副本最多三份；松手后没有补播；回落完成后恢复切换；紧接导航打开正确资料；阅读器 / 搜索输入键盘不受干扰；无 WebGL 回退也能限速。
- 浏览器压力阶段使用真实 RAF 与墙钟，暂跳过 GL 绘制以避免软件渲染器支配输入时序；开始时完整完成贴图烘焙，最终截图恢复实际 GL 绘制。该检查证明交互和资源数量约束，不代表用户设备的 FPS 改善幅度。

浏览器证据在 `docs/verification/rhine-navigation-limit/`。刷新 4177 或 DSH 中的莱茵界面即可加载新构建。
