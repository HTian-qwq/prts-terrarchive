# 阵列边缘清晰度

2026-09-12。用户指出阵列档案盒的顶边和竖边模糊，并确认截图使用性能档；切到极高档仍有虚化、外观也有变化。

## 原因与范围

- 旧性能档为 80% 渲染比例、1 倍像素密度上限、关闭抗锯齿，再放大显示。1302×950 的测试窗口只绘制 1041×760。截图所指的外壳仍是原几何，内构烘焙没有替换这些边缘。
- 工作台改变舞台的 CSS scale 后只通知独立查看器 resize。阵列仅观察自己的布局尺寸，等比例放大时该尺寸不变，因此沿用旧缓冲。实际复现 1302×950 → 1953×1425 后，旧缓冲仍为 1301×950，被放大约 1.5 倍。
- 默认工作台本身已启用 SMAA，但性能档会覆盖该设置。高／极高包含景深和环境遮蔽，画面风格与性能档不同；提高分辨率不会关闭景深虚化。默认与关闭景深的同姿态对照支持这一点，但不能据此断言用户所指极高档的所有外观问题都已定位。
- 当前 Three.js 0.183.2 的 SMAA 应在 OutputPass 之前；原顺序正确，没有调整。此次也没有增加 MSAA、锐化滤镜或改变模型材质。

## 修改

1. 性能档改为 100% 渲染比例和 SMAA。保留像素密度上限 1、1024 阴影、关闭 AO／景深、50% 透射分辨率和 4 倍纹理过滤。
2. 加载时只将完整匹配旧性能档的存储值映射到新性能档，其余自定义配置按原规则归一化。缺少字段的配置不会被当作旧预设；手动配置恰好与旧预设完全相同则无法区分来源，也会映射。迁移不立即重写 localStorage；之后用户改变画质时才按原机制保存。
3. 工作台按舞台宽高、缩放、布局种类及 DPR 变化通知阵列与查看器 resize，并更新实际画质摘要。相同布局不会重复调整缓冲；补充 window resize 监听。
4. 独立监听 resolution 媒体查询，在 DPR 改变时重新绑定查询并更新尺寸，覆盖没有 window resize 事件的像素密度变化。销毁时移除监听。

原始／高／极高预设、镜头、景深算法、透明盖板、阵列内构贴图、LOD 状态与模型池保持本次修改前的行为。

## 对照与成本

使用本机 Chromium／SwiftShader、1302×950 CSS 视口、DPR 1、十二份真实来源的浏览器内快照。初始化使用固定步长，跳过中间 GL draw；端点实际绘制三帧。同一组性能 A/B 的相机、档案姿态及虚拟时刻相同，设置仅影响隔离浏览器上下文。

| 指标 | 旧性能档 | 100%＋SMAA |
| --- | ---: | ---: |
| 实际缓冲 | 1041×760 | 1301×950 |
| 每帧绘制调用 | 52 | 55 |
| 各通道三角形提交 | 2,382,687 | 2,382,690 |
| AO／景深 | 关闭 | 关闭 |

目视对照中，顶边碎阶梯和竖边的放大模糊减轻，色调及性能档的光影保持一致。增加的三角形来自 SMAA 的三次全屏处理，并未增加模型几何。缓冲像素量增加约 56.2%，另有 SMAA 处理及其缓冲成本；这不是无代价的性能提升。

SMAA 第一次启用还会编译其着色器。软件渲染器中的 JS 回调、首次编译及截图等待时间不能代表硬件 GPU 帧率，此次未声称实际 FPS 改善。
