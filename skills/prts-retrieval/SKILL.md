# PRTS 资料检索

## 工作原则

先确认运行时注入的“本次会话资料模块”，再采用其模块说明。只查询已启用的资料模块；如果问题涉及未启用游戏，明确说明资料边界，不把另一款游戏的零命中写成“不存在”。`<prts:retrieval-context>` 只描述当前动态上下文快照对应的用户问题；新快照会取代旧快照，不得沿用旧块中的实体、关系或检索词。块内实时搭载范围与实体归属优先于会话创建时的范围。

按问题选择最短路线：

- 已知原句、专名、尚未定位的篇章或资料字段：`corpus_search`。
- 已有工具支持的稳定定位、行号，或需要连续阅读篇章/活动/任务：直接 `corpus_read`。
- 年代、活动时间和事件顺序：按当前模块说明选择时间线入口。
- 只记得一句官方剧情原文的大意且措辞可能不准：`cloud_search`，使用 `options.search_intent="single_sentence_search"`。
- 情节过程、关系、动机或多资料综合：默认 `cloud_search` 发现候选；需要精确台词、说话人、行动或因果时，再用映射出的标题与行号做本地核验。
- 云端不可用但本地足够时回退本地；工具故障不等于资料不存在。取得足够证据后停止。

## 证据和结论

官方剧情原文适合支持台词、行动、场景与上下文判断；官方档案等结构化资料适合支持身份和设定；Wiki、实体资料和时间线适合概括、清单、导航与候选发现。整理性材料中带引号的句子不能自动视为核验过的原文。实质冲突时回读相关原文上下文，并说明差异。

零命中只表示当前查询未命中。可根据原因缩短字面串、核对规范名、移除一个可能冲突的过滤条件，或改用适合模糊语义的云端路线。没有必要证据时说“当前资料未确认”。

## 回答与引用

- 先回答问题，再给必要依据；区分资料明示、整理性概括和推断。
- 原文引用采用工具返回的 `《完整展示标题》第 N 行`；其他资料使用用户可见标题。
- 不输出 `source_ref`、`document_id`、`entity_id`、cursor、`source_marker` 或内部路径。
- 外网只处理 PRTS 资料范围外的现实信息、时效公告，或用户明确要求联网的部分；不得静默替代游戏资料证据。

运行时会在下方附加当前启用游戏的模块说明、工具契约、推荐检索过程和对应问题配方。需要 Wiki 字段表时读 [Wiki 资料结构](references/wiki-schema.md)；遇到歧义、零命中或版本故障时读 [检索诊断](references/diagnostics.md)。
