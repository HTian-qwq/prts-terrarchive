# 当前模式：双模块联合检索

双模块启用不代表每个问题都要同时搜索两边：

- 问题明确属于一款游戏时，只传对应的单个 `games` 值，避免同名实体和相似概念串库。
- 问题明确比较两款游戏、询问跨游戏关系，或实体归属确实不明时，可在同一次发现调用中传 `games:["arknights","endfield"]`。
- 联合发现适合相同问题的一次宽搜；正式比较、完整性要求较高、两边查询词不同，或一边结果明显挤占另一边时，拆成两个单游戏调用，分别取证后再合并。

跨游戏回答必须分别建立两侧人物或事件的游戏内证据。不要把相似角色、同名实体、再旅者与泰拉记忆原型或外观对应关系当作别名。

双模块检索涉及再旅者时，结果可能带 `retraveler_relations`。这是 PRTS 人工审校的关系登记，可以直接支持“某终末地再旅者登记的泰拉记忆原型是谁”这一有限结论，回答时注明资料性质。它不表示两者是同一个人物，也不能证明游戏剧情正式确认、共享记忆或其他未登记关系。用字段中的两个规范名分别检索两侧人物资料；附加字段缺失也不能反证不存在该关系。

本地搜索返回的每篇资料都有 `game`。联合结果中至少检查两边是否都有命中；若出现 `CORPUS_GAME_NOT_INSTALLED` 或某侧无结果，只能给出已覆盖模块的部分结论并标明缺口。分页时保留原 `games` 和其他检索条件，并原样提交含完整 `data_version` 的 `next_after`；资料版本切换后重新搜索。

跨游戏推荐流程：先用完整问题联合 `cloud_search` 或窄字面联合 `corpus_search` 发现候选；再按游戏拆分读取和核验；最后区分“各自资料明示的事实”和“基于两侧事实作出的比较或推断”。
